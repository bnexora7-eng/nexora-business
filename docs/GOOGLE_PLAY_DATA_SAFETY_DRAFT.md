# NEXORA — Google Play Data safety form draft

**Status: working draft only — do not submit without checking the exact production build and server configuration.**

The Data safety form must describe the data actually collected or shared by the submitted app, its SDKs and the backend. This document is a preparation aid, not a legal determination.

## Candidate data types to review

| Play Console category | NEXORA data flow | Draft treatment |
|---|---|---|
| Personal info — Email address | Email used to register and sign in | Collected; required for account operation |
| Personal info — User IDs | Internal account ID and session association | Collected; account operation |
| Personal info — Other info | Business workspace notes may contain names or other details entered by the user | Review actual fields and user guidance |
| App activity / User-generated content | Community posts and Marketplace listings published by users | Collected; content is stored and visible to other users |
| App activity / Other user-generated content | Business workspace notes, goals and plans | Collected; account-associated and intended to be private |
| Financial info | Payment order amount, currency, provider reference and status | Current live checkout is disabled; reassess if Mollie checkout is enabled before submission |
| App info and performance | No third-party analytics/crash-reporting SDK was identified in the reviewed mobile package | Recheck the final dependency tree and SDKs |

Passwords are transmitted to the account API for authentication and stored server-side as salted scrypt hashes. Session tokens are generated by the API; only token hashes are stored in the session table.

## Sharing and service providers

- Render hosts the API and PostgreSQL database. Confirm its current data-processing terms, region and retention.
- Mollie receives checkout information only if payment checkout is enabled and used. Live checkout is currently disabled in Render configuration.
- The configured AI provider may receive business-planning prompts only if the AI planning endpoint is enabled and used. Confirm the provider and transfer configuration before enabling it.
- NEXORA does not use advertising SDKs or sell personal data, based on the current reviewed implementation.

Do not answer “not shared” until the service-provider processing flows and final production configuration have been reviewed against Google Play's definitions.

## Security and deletion answers to verify

- **Encryption in transit:** API and web requests use HTTPS in the deployed configuration.
- **Account creation:** Yes.
- **Account deletion:** Yes, an in-app deletion path and a public web deletion page are implemented.
- **Deletion scope:** account, sessions, Community posts, Marketplace listings and Business workspace are deleted. Payment ledger entries, if any, are detached from the account and may be retained where legally required; this retention must be clearly disclosed.
- **Independent security review:** not yet completed.

## Before completing the form

1. Freeze the exact AAB and its dependency/SDK list.
2. Confirm Render environment variables and whether Mollie/AI are enabled.
3. Confirm every field collected by the app and backend, including diagnostic/logging data.
4. Confirm service-provider contracts, processing locations and international-transfer safeguards.
5. Complete the Data deletion questions consistently with the privacy policy and the account-deletion web page.
6. Have the responsible operator review the final answers and privacy notice.

Google Play's Data safety answers are developer declarations. Do not use this draft as a substitute for reviewing the final build and actual data flows.
